# Spondee Frontend Design

Status: finalization / pre-deployment review

## Surface Modes

Marketplace and category pages persuade a cold judge to start the core path. Agent, Promise, Activation, Receipt, Replay and Evidence pages operate as proof surfaces.

## Visual Thesis

Premium DeFi marketplace meets evidence terminal: near-black canvas, quiet layered surfaces, warm off-white text, restrained gold action color, compact proof blocks and direct labels. The UI should feel like a serious user is granting financial authority only after seeing the agent's precommitted promise.

The visual treatment must remain domain-native rather than generic AI SaaS. BNB Chain, bounded ERC-8183 activation, Promise/Receipt provenance and measured evidence should appear where they explain the mechanism, not as decorative badge walls.

## Copy Tone

Use concrete product language: promise, authority, activation, receipt, replay, observed evidence, baseline. Avoid inflated claims, generic AI phrasing and unsupported performance language. Negative and neutral outcomes are evidence, not failures. SIMULATION and OBSERVED must remain visually and verbally distinct.

Canonical repository-preserved observed evidence may be surfaced as a structured summary when it is explicitly labeled as canonical preserved evidence and kept separate from the current runtime-store state. Never reconstruct missing runtime EvidenceRun payloads from prose.

## Components

Cards are for meaningful objects: category, agent, Promise Card, receipt panel, evidence run. Proof metadata belongs near the result it validates. Primary actions use verbs and should sit close to the decision they complete.

## Judge Path

The first view should establish four facts without requiring documentation:

1. Spondee is a BNB Chain agent outcome marketplace.
2. The agent commits to a task-specific Promise before bounded authority is granted.
3. Four BSC-testnet activation paths have been verified.
4. Three countable observed Agent Advantage pairs are preserved, including negative and neutral results.

Primary signature path: `Start Health Factor path -> Configure -> Promise -> Activate -> Receipt -> Compare`.

## Responsive Rules

Mobile stacks proof panels into one column, preserves the main call to action, and avoids horizontal scroll for IDs, JSON, transactions and long backend labels. Tables and definition grids collapse before they become cramped.

## Accessibility

Use semantic headings, links, buttons, form labels and definition lists. Focus states remain visible. Status is expressed with text plus icon/color, never color alone. Motion must respect reduced-motion preferences.

## Anti-Patterns

No fabricated or unverified evidence counts, fake live indicators, guaranteed profit/safety claims, neon casino styling, generic AI SaaS copy, badge walls or decorative gradients that obscure product truth. Repository-preserved verified evidence summaries are allowed only when their source and separation from runtime-store evidence are explicit.
